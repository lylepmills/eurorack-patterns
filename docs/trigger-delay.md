# Bounded trigger delay

`TriggerDelay<MaxDelayTicks>` in [trigger_delay.h](../include/eurorack_patterns/trigger_delay.h) delays up to 32 logical trigger inputs. The caller passes a bitmask and a delay measured in **calls to `Tick()`**. Schedule inputs for the current tick before calling `Tick()`: delay zero is emitted by that call; delay N is emitted by the Nth later call. `Tick()` returns all due input bits, clears that deadline, and advances exactly one tick. The maximum is inclusive, and `MaxDelayTicks = 0` is valid.

The implementation has `MaxDelayTicks + 1` fixed `uint32_t` buckets plus an index. `Schedule` and `Tick` take constant time; construction and `Reset` clear all buckets. There is no allocation, wall clock, exception, or hidden catch-up. `Schedule` returns `false` without changing pending events if the requested delay exceeds the maximum. An empty mask is an accepted no-op. Both simultaneous distinct inputs and successive edges on the same input with different due ticks survive. Scheduling the same input bit twice for one due tick coalesces to one output bit, so this is inappropriate when same-tick multiplicity matters. Delay changes affect new schedules only; pending deadlines keep their original due ticks.

Call `Schedule`, `Tick`, and `Reset` from one owned context, or provide external synchronization. A missed `Tick()` delays every pending event by a real-time interval because this class knows only call count. The host must choose a fixed cadence, catch up deliberately by calling `Tick()` for each missed interval, or cancel pending events. It must also decide what to do on transport stop, preset change, and panic. The class does not sample electrical inputs, detect edges, or establish CV-before-trigger timing on hardware.

The design was prompted by [O_C's per-input trigger-delay fix](https://github.com/mxmxmx/O_C/commit/cc2b6985c71a5aab5de8eba7a992b191b261a511). An earlier single pending mask could be overwritten by a later input before its delay matured. This implementation is original MIT code organized as a ring of deadline masks, rather than O_C's per-input shift registers. The synthetic host test replays A at tick 0 and B at tick 1, both delayed three ticks, and checks A at tick 3 and B at tick 4; the [gallery](gallery.md#trigger-delay) plots that replay against a single shared pending mask. It also checks independent absolute deadlines against a map oracle, invalid delays, coalescence, the highest mask bit, reset, and ring wrap. These host checks do not establish hardware timing or electrical behavior.
