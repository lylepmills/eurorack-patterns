# Logical pulse timer

[`PulseTimer`](../include/eurorack_patterns/pulses.h) models one output's active interval in caller-supplied `uint32_t` ticks. Configure a width and choose `kRestart` or `kIgnoreWhileActive`, then call `Trigger(now)` on an event and `Advance(now)` when servicing outputs. Read `active()` to drive the physical output. A successful `Configure` or `Cancel` makes it inactive immediately; update the output at that call site. One caller must own all access, or provide its own synchronization.

`Trigger` first expires a pulse whose deadline has passed. It returns `true` when the trigger is accepted, including a restart of an already-active interval. It returns `false` when unconfigured, disabled with width zero, or ignored during an active interval. `Advance` returns `true` only when that call expires an active interval. `Cancel` returns whether one was active. Invalid configurations (width at least `2^31`, or an unknown policy) return `false` without changing configuration or state. A valid configuration cancels the old interval and latches the new width for later triggers.

Both retrigger policies **coalesce events**. With a 10-tick width, triggers at ticks 0 and 5 keep `kRestart` active through tick 14 and make it inactive at tick 15. `kIgnoreWhileActive` rejects the second trigger and expires at tick 10. Neither policy creates a fresh edge at tick 5. If distinct triggers are required, the host needs a separate bounded event queue and an output scheduler that provides a minimum inactive interval; this timer does not do that.

Even an accepted trigger **after** the old deadline may produce no new physical edge: `Trigger` expires and re-arms internally, and its final state is active. If the host never serviced the expired low state, its pin can have remained high throughout. `Trigger` reports acceptance, not delivery of a pulse edge.

Timestamps must move forward modulo `2^32`, with less than `2^31` ticks between calls; widths must also be less than `2^31`. This permits wraparound comparisons without a separate epoch. The timer knows only logical time: if `Advance` is called late, the pin remains in its old state until the host writes the new one. Actual pulse width, edge jitter, and low-gap guarantees require measurement with the intended output service path and receiving module. For example, a 3 ms logical pulse serviced only at 0 and 10 ms can remain physically high for 10 ms.

The design was informed by monome Teletype's documented [pulse-timing fix](https://github.com/monome/teletype/pull/310) and [per-output timer behavior](https://github.com/monome/teletype/blob/e390bacdf024f2234e2ade6a4821773b9a80a322/module/main.c#L1051-L1076).
